# 機能開発は設計から

新しい機能を開発するときは、コードを書く前に `docs/` 配下に機能ごとのディレクトリを作り、設計を書く。

## 手順

1. `docs/<機能名>/` を作る。機能名は英小文字のケバブケース（例: `docs/contact-form/`）
2. `docs/<機能名>/design.md` に設計を書く
3. 設計を書き終えてから実装に入る
4. 実装中に設計と食い違ったら、先に `design.md` を直してからコードを直す

## design.md に書くこと

- 目的: 何のための機能か
- 要件: 満たすべきこと・やらないこと
- 仕様: 画面・振る舞い・データの形
- 実装方針: 触るファイル、追加するファイル
- 未決事項: 決まっていないこと

図・画面案などの補足資料は同じディレクトリに置く。

## 対象外

- 誤字や文言の修正、1ファイル内で完結する小さなバグ修正
- 既存機能の改修は、その機能の `docs/<機能名>/design.md` を更新してから進める
